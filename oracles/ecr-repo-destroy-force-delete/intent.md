One ECR repository exists. Image scanning on push is enabled on it, and a lifecycle policy expires images by image count, keeping the most recent 10: every rule that expires by image count keeps 10 and applies to images of any tag status, so the repository retains 10 images — not 10 of one kind alongside 100 of another, and not 10 untagged images alongside an unbounded number of tagged ones. Deleting the repository leaves the account clean: the delete succeeds even though the repository still contains images, without deploying any additional resource to make that true.
That last sentence is the requirement, and the arms make it observable in different places, which this oracle records rather than flattens. On every Terraform-shaped arm the deployed configuration is what proves it: the plan carries an ordinary boolean whose absence looks exactly like a correct configuration for an empty repository, so NO static assert reads it and the agent's own `terraform destroy` — run by the teardown tier against a repository the live check has just pushed an image into — is the oracle. On awscdk the template is what proves it, and must be: the CDK default removal policy is `Retain`, under which `cdk destroy --force` succeeds while leaving the repository in the account, so a destroy-based verdict there would report a clean teardown for a repository that survived it. That arm therefore requires `DeletionPolicy: Delete` at tier 0 and, at tier 1, `EmptyOnDelete: true` with no `Custom::ECRAutoDeleteImages` resource anywhere in the template — the registry's own native behaviour, not an added custom-resource Lambda that empties the repository on the way down.
