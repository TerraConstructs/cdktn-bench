What aws-bench Actually Provides

Upstream ships a contract, not oracles: a reward file, a role per phase, four scenario phases, and a per-account admission gate. Every oracle notion cdktn-bench uses — tiers, live_check.py, gating, idempotence, run_invalid — is a downstream construction inside the one slot upstream leaves free-form, tests/test.sh. That is the right place for it, and the one place the two disagree is how a rewardless trial is counted.

2 · How upstream tasks grade live

There is no assertion library and no live-check contract. The framework's entire contribution is credential staging: _staged_credentials(RoleType.VERIFIER) assumes the phase role in every account tag, writes a per-tag ~/.aws/credentials as the stage's user, blanks the raw AWS_* env so host creds cannot outrank it, sets AWS_PROFILE to the first tag, and deletes the file on exit. test.sh then calls boto3 or the CLI however it likes. AB/task/aws_trial.py:166-225, 366-388

  • Roles: RoleType = AGENT | VERIFIER | PRE_INVOKE | POST_INVOKE, each mapped to a [scenario].<phase>_role_name. Undeclared → OrganizationAccountAccessRole. Every assume chains through the org role first; session names are aws-bench-<role>-<task>-<job>. AB/task/aws_creds.py:52-71 · AB/utils/credentials_provider.py:337-400
  • Placeholders: {{Export}} / {{TAG::Export}} in [verifier].env, instruction and [solution.env], fed by config.exports + pre-invoke's placeholder.json. AB/task/aws_creds.py:35-49 · AB/task/aws_trial.py:299-321
  • Outcome vocabulary: a float, bucketed to correct_response / no_response / wrong_response — agent behaviour, not verifier trust. A verifier that could not determine anything has no way to say so. AB/metrics/aggregation.py:73-79
  • Timeouts: verifier 600 s (→ VerifierTimeoutError), agent unbounded, phase scripts 600 s, build 600 s. Trial retries default 0, and reward-file errors are explicitly excluded from retry — a broken oracle fails loudly. HB/models/job/config.py:217-232
  • No eventual-consistency loop in verification; the only poll helper is wait_for_role for IAM propagation on fresh accounts. AB/utils/credentials_provider.py:402-449
  • Two upstream oracle families (README): introspection tasks scored by an LLM judge (rationale parsed from reward-details.json), and mutation tasks checked programmatically against live state then rolled back. METADATA:91-94 · AB/metrics/run_data.py:75-128

QALocalInvocationApplicationRole / …Admin are not aws-bench constants — they are values this repo puts in task.toml and deploys from scenarios/anchor.

4 · Multi-step

Harbor's MultiStepTrial is complete — sequential [[steps]] with per-step instruction/tests/solution, min_reward early abort, FINAL or mean aggregation, per-step verifier modes and timeouts. HB/trial/multi_step.py:18-379 aws-bench refuses it at the factory: NotImplementedError("per-step pre/post-invoke credentialing is undefined"), so all AWS behaviour exists only on the single-step path. AB/task/aws_trial.py:437-449

cdktn-bench's CdktnMultiStepTrial(MultiStepTrial, AwsBenchSingleStepTrial) composes both by MRO and supplies exactly the missing piece — a per-step credentialed steps/<name>/pre_invoke/pre_invoke.sh reusing upstream's ScriptRunner and _staged_credentials — plus a FINAL default (Harbor's mean + min_reward abort can score "failed step 1, never ran step 2" above "ran both, failed step 2"). Ownership of every method is pinned by test_trial_mro.py. CB/cdktn_bench/trial.py:93-272

5 · Results and the missing "invalid row"

result.json carries verifier_result.rewards, agent_result (tokens, cost), exception_info, four timing spans, and step_results; turns and tool calls are derived from agent/trajectory.json. HB/models/trial/result.py:69-129 · AB/metrics/run_data.py:302-399

Judgement and follow-ups

cdktn-bench is a well-behaved downstream: it adds an oracle grammar in the one free-form slot and reuses the reward file, ScriptRunner, credential staging, placeholders, contamination, admission gate and reset verbatim. Three things worth acting on:

  1. Own the aggregation for rewardless rows. Upstream's accuracy counts a run_invalid trial as a failure. Confirm metrics/ and gates/emit_result.py never route through aws_bench.metrics.aggregation for headline numbers.
  2. Move gate detail into reward.json. Keep reward as the AND-collapsed headline key for upstream compatibility and add static, live, idempotence keys alongside — no side-file parsing needed for per-tier analysis.
  3. Upstream PR: trial_factory on AwsBenchTrialQueue and an injectable job class. Deletes cdktn_bench/queue.py's copied loop and the monkeypatch, and removes the drift test's reason to exist.
