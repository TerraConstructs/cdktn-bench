## The pattern in the includes: two new harness capabilities

**1. Multi-step trials** (the big one — quoted repeatedly: "current aws-bench
uses SingleStepTrial from Harbor — may need to vendor some of aws-bench and
implement multi_step"). Needed when the *second intent must not be visible at
step one* (else the agent avoids the trap by planning ahead) or when an
out-of-band event happens mid-trial:
- `drift-blindness` (harness mutates infra out of band → re-prompt agent)
- `sg-inline-vs-standalone-rules` (step 1 wants inline rules → deploy;
  step 2 adds a rule as a separate resource → deploy; revealing both upfront
  defeats the trap)
- `cross-stack-export-deadly-embrace` (step 2 = stop consuming the reference)
- `rds-blue-green` (also slow-resource; tcons RDS L2s pending in stacked PRs
  — L1 binding may suffice meanwhile)
- `s3-notification-on-unowned-bucket` (plus unowned-fixture; operator note:
  Terraform arguably WORSE — no UPSERT, flip-flop across owners — re-examine
  arm prediction)

**2. Poisoned workspace** (cheaper; generator/scenario setup writes EXISTING
config that carries the latent pitfall; the prompt is a change request or an
observed failure symptom; "we measure tokens to green per arm" on brownfield):
- `named-resource-replacement-create-before-destroy` (existing config with
  explicit `name`, no CBD; trap fires on the agent's own 2nd apply — works
  single-step once the workspace is pre-seeded)
- `s3-acl-vs-object-ownership-log-delivery`, `singleton-child-resource-clobber`,
  `lambda-alias-tracks-unpublished-latest` (needs pre-deployed *state*, not
  just code — heavier), `policy-json-string-normalization-diff`.
- Note on `policy-json-normalization`: multi-step is NOT required — poisoned
  workspace + the *verifier* running the second `plan -detailed-exitcode`
  (idempotence oracle) fires the catch without re-prompting the agent.
