The Mock Endpoint Problem

Two Terraform arms each ship their own loopback HTTP stub so an offline terraform plan can resolve. They work — but they live in the agent's workspace, they are arm-asymmetric, and the port collision everyone worries about is not the one that actually bites.

Why they exist at all

Both arms hit the same class of defect: the provider's skip_* flags suppress the provider's own bootstrap calls, and nothing else.

The language split is a consequence of the image contracts, not taste: hcl-raw's image is Debian plus terraform/opa/jq/awscli with no node, so Python's stdlib http.server was used — and Python was added to that image specifically for this fixture. Both are dependency-free and bind loopback only, so they work under --network none.

The hcl-raw case is tracked upstream as hashicorp/terraform-provider-aws issue #39472 and reproduced against the pinned provider 6.58.0.

How it works today

Containers do not share the host network

Harbor runs the agent container through docker compose with a main service and the default bridge network — or network_mode: none when internet is disallowed. Neither is host networking. Each container therefore has its own network namespace and its own private 127.0.0.1, so a fixed port is genuinely private per trial. Loopback works even under --network none, because lo exists in every namespace.

So concurrency between trials was never at risk from these mocks.

The gates are where it bites

gates/oracle_falsifiability.py does not run the container. It copies the task into a scratch directory, runs npm ci for real, and patches static_tiers.sh's absolute /app/project and /logs/verifier paths to point at that sandbox — so the whole chain, mock server included, executes on the host. Every concurrent gate process then races for the same host port.

Observed this session: one grading-proof run scored a correct terraconstructs solution 0.0; an immediate re-run of the identical command scored it 1.0. The log showed EADDRINUSE 127.0.0.1:17771. The mock-sts-unavailable guard that exists to label exactly this case did not fire — so it surfaced as TF-PLAN FAILED, indistinguishable from a bad solution.

The real cost: workspace pollution, and it is arm-asymmetric

Both fixtures are byte-copied into the task's environment/, which is COPY'd into the agent image. That means they sit in the agent's own working directory:

awscdk           (nothing)
hcl-raw          environment/workspace/mock-sfn.py     -> /app/project/mock-sfn.py
terraconstructs  environment/app/mock-sts.js           -> /app/project/mock-sts.js

The agent on two of three arms opens its workspace and finds a mock AWS server it did not write and is not asked about — and the third arm has no such file. That is a visible, arm-asymmetric difference in the starting workspace of a benchmark whose headline metric is tokens-to-green. Any turn spent reading or reasoning about that file is spend the awscdk arm never incurs.

They are always started regardless of need, so 16 of 17 specs ship an SFN mock that is a pure no-op — and every terraconstructs task ships an STS mock whose comment block explains a provider-internals problem the agent is not being tested on.

A better design

Harbor already has the mechanism. It is not being used.

Sidecar service via extra_docker_compose_paths

harbor/environments/definition.py accepts extra_docker_compose_paths and treats a task-supplied environment/docker-compose.yaml as a first-class environment definition. Harbor already composes overlays this way — docker-compose-prebuilt.yaml for the image, docker-compose-no-network.yaml to force network_mode: none.

A second service on a compose network gives the mocks a DNS name instead of a port number:

services:
  main:
    depends_on: [aws-stub]
  aws-stub:
    image: cdktn-bench/aws-stub:pinned
    # no ports: — reachable only on the compose network

The provider config then points at http://aws-stub:443 rather than http://127.0.0.1:17771.

What it fixes

  • No workspace pollution. The stub is a container, not a file in /app/project. The agent's workspace becomes identical in shape across all three arms.
  • No fixed host port. Compose gives each project its own network; two gate runs get two networks and cannot collide. The EADDRINUSE class disappears rather than being worked around by "run the gates serially".
  • One stub, both arms. STS and SFN are two routes on one service. No reason for a Node one and a Python one — that split exists only because each fixture had to run inside its own arm's image.
  • Pinned and versioned. A stub image carries a digest, so "which stub answered" becomes part of trial identity instead of an unversioned file copy.
  • Startup is compose's job. depends_on plus a healthcheck replaces the hand-rolled "start it, poll the port for 5 s, kill it" wrapper in static_tiers.sh — and with it the guard that failed to fire.

What it costs, honestly

  • The gates still run on the host. This is the important caveat: a compose sidecar helps the trial path, but oracle_falsifiability.py deliberately runs static_tiers.sh outside a container. Either the gates move into compose too, or they need their own answer — an ephemeral port would do.
  • network_mode: none conflicts. A service on a compose network cannot also be on no network. Offline isolation would have to be expressed as an internal network with no gateway rather than as none.
  • Equipping hash churn. Adding a service changes the environment definition for every task, so every existing row lands in a different stratum. Worth doing once, deliberately — not incrementally.
  • A second image to build and pin, and colima's compose plugin becomes a hard requirement rather than a convenience.

Cheaper interim step

If the sidecar is too large a change to make now, the collision itself is fixable without it: bind an ephemeral port (:0), have the stub print the port it got, and pass that into the provider config instead of hardcoding 17771. That removes the shared global entirely and costs nothing in strata. It does not fix workspace pollution or the arm asymmetry — those need the stub out of /app/project.
